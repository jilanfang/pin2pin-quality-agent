# 8D Copilot 产品路线图

## 1. 文档目的

记录当前已经达成的产品方向共识，尤其是：

- 当前阶段到底做什么
- 明确不做什么
- 下一阶段可能往哪里演进

这份文档的重点不是详细排期，而是避免团队在后续迭代中忘记已经达成的路线判断。

## 2. 当前产品定位

当前对外主叙事：

`异常响应 Copilot`

当前第一落地形态：

`8D / 异常报告初稿生成与引导`

当前主付费人群：

- 愿意自己为 AI 服务付费的年轻工程师

当前辅助资源人群：

- 老工程师

老工程师在当前阶段的角色不是主要付费用户，而是：

- 提供经验
- 帮助校准方法论
- 直接推荐年轻工程师用户

## 3. 当前阶段必须聚焦的事

当前最小可卖版本不是一个大而全的质量平台，而是一个能帮助年轻工程师尽快交出一版像样报告的工具。

当前阶段必须成立的价值链路：

`碎片输入 -> AI 判断场景 -> 引导补齐信息 -> 输出可交付初稿 -> 用户建立信任`

当前同时覆盖两个真实场景：

- 客户投诉 / 对外回复
- 内部异常 / 测试失效 / 失效分析

但是这两个场景共享一套核心承诺：

`帮助用户把异常信息整理清楚，并生成一版可交付初稿`

## 4. 当前交互共识

### 4.1 总体方向

交互要尽量偏 `AI native`，尽量少按钮、少表单、少系统感。

目标不是让用户“学习一套 8D 系统”，而是让用户感觉自己有一个会办案、会追问、会帮他整理线索的副驾。

### 4.2 已确认的交互判断

- 默认走 `新手引导模式`
- `专业阶段模式` 不作为默认入口，而是在流程中逐步显露
- 不要求用户一开始就理解 `D1-D8`
- AI 先根据用户输入自动判断场景，再用一句话向用户确认
- 首页主舞台应该是 `案件工作台`

### 4.3 案件工作台的当前理解

第一阶段的工作台不等于复杂画布，也不等于传统表单。

它更像一个围绕案件展开的 AI 工作区：

- 中间承接对话和线索输入
- 周边逐步长出事实、缺口、阶段进度和初稿
- 报告是结果，不是首页主角

## 5. 当前阶段明确不做的事

为了让产品尽快进入市场验证，当前阶段明确不做：

- 不做大而全质量平台
- 不做重型团队协作系统
- 不做复杂审批流
- 不做过多入口选择
- 不做大量按钮驱动的传统软件交互
- 不把首页做成纯报告编辑器
- 不在当前阶段做“探案画布”式复杂交互

## 6. 后续路线备忘

下面这些方向被认为有潜力，但不进入当前最小可卖版本。

### 6.1 探案式 AI 画布

这是一个明确值得保留的未来方向。

原因：

- 8D 分析本质上就是一个逐步收集证据、识别矛盾、形成假设、验证结论的探案过程
- 这种隐喻和产品体验天然匹配
- 如果当前的案件工作台跑通，后续非常适合演进成“福尔摩斯探案式”的 AI 画布

未来画布可能包含：

- 线索区
- 已知事实区
- 假设与待验证区
- 因果链或分析链
- 关键缺口提示
- 报告草稿联动视图

但当前结论是：

`现在不要做画布。`

先把最小工作台和首个可卖价值做成立，再考虑往画布演进。

### 6.2 方法论资产化

后续值得继续建设：

- 更完整的 8D 方法论库
- 不同行业 / 场景的异常分析提示
- 老工程师经验沉淀
- 相似案例推荐

### 6.3 输出能力升级

当前已经明确的方向：

- 输出不应只有一种形式
- 需要同时支持：
  - `文本`
  - `正式报告`

当前阶段结论：

- `文本` 负责复制、适配公司模板、灵活编辑
- `正式报告` 负责建立专业感和交付感
- 当前只做一套中文正式工程报告 HTML 风格
- PDF 走 `HTML -> PDF`，不单做一套独立系统

后续值得继续建设：

- 多风格正式报告
- 公司品牌化模板
- 客户模板映射
- PDF 高级导出

### 6.4 更强的引导式交互

后续值得逐步增强：

- 更聪明的信息搜集顺序
- 不同场景下不同的提问策略
- 更自然的“为什么问这个问题”解释
- 更强的事实 / 假设 / 待验证标记

## 7. 当前优先级总结

如果后续要继续推进，优先级应该是：

1. 打磨步骤流程
2. 打磨与用户的交互方式
3. 补强 8D 方法论和引导能力
4. 提高初稿质量和可信度
5. 打磨文本 / 正式报告双输出
6. 再考虑更高级的工作台表达
7. 最后才考虑探案画布

## 8. 一句话提醒

当前阶段先把：

`异常响应副驾 + AI native 案件工作台 + 可交付初稿`

做扎实。

未来再把它演进成：

`福尔摩斯探案式 AI 画布`
