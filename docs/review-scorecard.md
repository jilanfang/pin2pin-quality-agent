# 8D 工具 Review 评分卡

## 1. 文档目的

这份评分卡用于当前 `8D / 异常响应工具` 项目。

它的作用是把每次 review 从“感觉不错 / 感觉还差点”变成一个更稳定、可比较的评分过程。

## 2. 使用方式

每次 review 至少找 3 个案例来打分：

- 客户投诉 / 对外回复案例
- 内部异常 / 测试失效案例
- 信息特别碎的案例

每个维度按 `1-5` 分打分：

- `1` = 明显不可用
- `2` = 很不稳，明显会挡住真实使用
- `3` = 基本可用，但仍会明显影响信任或转化
- `4` = 较好，已经能支持真实用户测试
- `5` = 很强，已经接近小范围收费测试水平

## 3. 五大评分维度

### 维度 1：首次上手清晰度

问题：

- 用户第一次进入时，知道自己要做什么吗？
- 页面和交互会不会让他感到压力？
- 他能不能在很短时间内开始投材料？

评分参考：

- `1`：明显看不懂，像系统而不是助手
- `3`：能理解，但仍有明显犹豫和混乱
- `5`：非常顺，用户自然就开始使用

### 维度 2：信息搜集引导质量

问题：

- 系统问的问题是不是关键问题？
- 顺序是否合理？
- 问法是否像在帮忙，而不是在审问？

评分参考：

- `1`：问题泛泛、顺序混乱、用户容易烦
- `3`：基本可用，但还不够聪明
- `5`：用户会明显感觉“这个系统真的懂我要补什么”

### 维度 3：方法论专业度

问题：

- 是否体现 8D / 异常分析方法论？
- 是否能区分事实、假设、措施和待验证项？
- 是否能避免明显空泛和错位？

评分参考：

- `1`：像普通 AI 润色器
- `3`：有方法论影子，但不够稳
- `5`：让老工程师也觉得“这套逻辑是靠谱的”

### 维度 4：初稿可交付度

问题：

- 当前产物是否足够像真实工作底稿？
- 用户是否敢拿着它继续修改、继续提交？
- 是否清楚、专业、不过分 AI 腔？

评分参考：

- `1`：像样子货，不能用
- `3`：勉强能作为草稿，但可信度一般
- `5`：已经能支持真实工作流中的初稿交付

### 维度 5：付费意愿强度

问题：

- 用户会不会觉得“这东西真能帮我省事”
- 用户是否愿意在真实场景中继续使用
- 用户是否愿意为这种结果付费

评分参考：

- `1`：用户只会觉得有趣，不会买
- `3`：有价值，但还不够让人掏钱
- `5`：用户在真实场景里很可能愿意直接付费

## 4. 阻塞判断规则

### 单项 blocker 规则

任何一个维度低于 `3` 分，都应该被视为 blocker。

### 总体判断规则

- 平均分 `< 3`：
  - 不可上线
- 平均分 `3 - 3.9`：
  - 可继续内测，不建议收费
- 平均分 `4 - 4.4`：
  - 可进入真实用户测试
- 平均分 `4.5+`：
  - 可考虑进入小范围收费测试

## 6. 推荐 review 节奏

建议每次重要迭代后都做一次评分 review：

- 流程发生明显变化时
- 方法论提示明显变化时
- 初稿生成策略变化时
- 准备拉真实用户测试时
- 准备开始收费测试时

## 7. 一句话提醒

这个评分卡不是为了证明“我们做了很多功能”，而是为了判断：

`这个 8D 工具是不是已经足够让年轻工程师信任，并愿意继续用下去。`

## 8. 当前阶段推荐用法（2026-03-22）

基于当前 CEO review，评分卡的推荐用法是：

- 现在主要用于判断：
  - 是否可以进入封闭真实用户测试
- 现在暂时不用于判断：
  - 是否应该公开收费

当前默认解释建议：

- 平均分 `4 - 4.4`：
  - 进入封闭真实用户测试
- 平均分 `4.5+` 且没有单项 blocker：
  - 才讨论小范围收费测试

当前阶段尤其要重点看这三个维度：

- 信息搜集引导质量
- 方法论专业度
- 初稿可交付度

如果这三个维度里任何一个没有稳定到 `4` 分以上，就说明：

`产品还没有穿过“真实工作流信任验证”这道坎。`
