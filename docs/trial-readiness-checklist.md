# 8D Copilot 试用前准备清单

## 1. 文档目的

这份清单不讨论长期路线，也不讨论完整商业化。

它只回答一个更实际的问题：

`在正式做官网和更大范围导流之前，ai-quality 还需要准备什么，才能让真实用户快速用起来，并尽快给出有效反馈？`

这份文档偏执行，不替代：

- [上市准备检查](./launch-readiness.md)
- [Demo 运行与部署说明](./deployment-and-demo.md)
- [GTM](./gtm.md)

它的作用是把“让用户快速试用并给反馈”这件事，拆成一份更短、更直接的准备清单。

## 2. 当前判断

当前阶段最重要的不是继续扩页面，也不是先上支付。

最重要的是先把这 6 件事补齐：

1. 稳定可访问的试用入口
2. 3 分钟能跑通的首单路径
3. 页面内反馈入口
4. 最小行为埋点
5. 明确的反馈问题集
6. 一批真实种子用户的试用组织方式

如果这些没准备好，官网只会把更多用户更快送进一个还收不到有效反馈的系统。

## 3. P0：必须先做

### 3.1 稳定试用地址

必须具备：

- 一个真实用户可直接访问的公开试用地址
- 不是只靠 `localhost`
- 不是只能让创始人本机演示

当前建议：

- 按 [Demo 运行与部署说明](./deployment-and-demo.md) 先上一个稳定 preview
- 优先考虑 Vercel preview / demo 环境

### 3.2 持久化存储

对外试用必须避免“数据随便丢失”。

必须具备：

- 至少一个可跨重启保存案例数据的环境

当前建议：

- 对外试用环境优先使用 `Postgres`
- 不继续把“本地文件模式”当成正式试用环境

### 3.3 首单路径

真实用户第一次进入后，必须能在 3 分钟内完成第一轮有效操作。

至少要支持这两条入口：

- `加载种子案例`
- `新建空白案件`

并且用户需要在非常短时间内做到：

- 进入工作台
- 发送第一条证据
- 看到第一版结构化结果或报告预览

### 3.4 首屏引导

工作台不能假设用户天然知道下一步怎么做。

必须补齐：

- 进入后的第一步提示
- 空状态说明
- “先做什么”提示
- “什么时候能看到结果”提示

目标不是让用户学会完整 8D，而是先让用户能开始。

### 3.5 页面内反馈入口

必须把反馈入口做成产品的一部分，而不是靠用户自己找你。

至少要有：

- 固定可见的反馈入口
- 简短反馈分类

建议分类：

- 看不懂怎么用
- 结果不专业
- 有 bug / 报错
- 其他建议

### 3.6 最小行为埋点

如果没有行为数据，后续只能靠印象改产品。

第一批必须记录：

- 打开工作台
- 新建案件
- 加载种子案例
- 发送第一条证据
- 生成报告预览
- 生成 final
- 页面或接口报错

### 3.7 种子用户试用组织

不能只让用户“随便试试”。

必须提前准备：

- 第一批种子用户名单
- 每个人的来源
- 每个人的角色
- 谁属于深度共创型
- 谁属于普通试用型

目标是让第一批试用有结构，而不是随机。

## 4. P1：很快补上

### 4.1 工作台价值表达

当前工作台更像 demo，需要更明确地告诉用户：

- 这个工具到底在帮什么
- 为什么它不是普通 AI 聊天框

### 4.2 种子案例演示路径

种子案例不仅要“能加载”，还要像一个真正的演示入口。

需要让用户：

- 一看就知道为什么该先点它
- 跑完后能理解产品能力边界

### 4.3 错误提示与空状态

失败时如果提示不清，反馈会失真。

要尽快补：

- 明确报错文案
- 空状态指引
- 异常状态后的恢复路径

### 4.4 试用后反馈

建议在用户第一次生成预览后，加一个非常短的反馈动作。

建议只问两件事：

1. 这版结果有帮助吗
2. 你下一步最卡的是什么

### 4.5 品牌露出

工具页需要至少体现：

- `Pin2pin.ai`
- `8D Copilot`

否则未来从官网跳进来时，用户会感觉进了另一个不相关产品。

## 5. P2：可以晚点做

这些不是当前试用反馈闭环的前置条件：

- 登录 / 账号体系
- 邀请 / 组队 / 返佣
- 支付与订阅
- 多工具统一导航
- 复杂团队协作权限
- 完整企业后台

## 6. 当前最该看的验收标准

在继续扩大导流之前，至少要满足下面 3 个判断：

### 6.1 首单可用性

一个真实用户能不能不靠创始人解释，自己开始第一单。

### 6.2 反馈有效性

用户第一次使用后，能不能明确说出：

- 产品到底在帮什么
- 自己卡在哪一步
- 输出结果是否“像回事”

### 6.3 数据可见性

团队能不能看到：

- 用户在哪一步离开
- 哪一步最容易卡住
- 哪些错误最常见

## 7. 对 ai-quality 的直接任务翻译

如果把上面这些要求翻成当前项目的直接待办，优先级如下：

### P0

- 部署稳定 preview 环境
- 接通 `Postgres`
- 强化工作台首单引导
- 页面内加入反馈入口
- 增加最小埋点

### P1

- 强化种子案例入口
- 补错误提示与空状态
- 增加第一次预览后的反馈动作
- 补品牌露出

### P2

- 登录 / 支付 / 邀请 / 团队协作能力

## 8. 一句话结论

在正式做官网和更大范围导流之前，`ai-quality` 最先要补的不是更多营销层，而是：

`稳定入口 + 首单引导 + 反馈入口 + 埋点 + 种子用户试用组织。`
