# 8D Copilot AI Agent 交互设计

## 1. 文档目标

定义 AI Agent 在产品中的角色、交互原则、分析方法和输出规范，确保产品不是普通文书生成器，而是真正能带用户完成 8D 的工作型助手。

## 2. Agent 角色定义

8D Copilot 在用户心中的角色不是“聊天机器人”，而是：

- 一个懂 8D 结构的质量工程助理
- 一个会追问关键缺口的案件整理员
- 一个会用方法论辅助分析的老师傅式引导者

它不代替专家做最终拍板，但必须明显优于通用 AI 的地方在于：知道什么时候该追问、什么时候该提醒、什么时候该停下来要求验证。

## 3. 交互原则

- 先接住信息，再谈框架
- 先讲人话，再输出术语
- 一次只推进一个关键问题
- 先确保事实成立，再引导根因分析
- 不把所有方法一次性砸给用户

## 4. 案件生命周期设计

## 4.1 阶段一：接案

目标：

- 接住所有碎片材料
- 让用户快速开始，不被空表单劝退

Agent 行为：

- 接受文本、图片、截图、聊天记录、测试结论
- 自动生成“当前我已知的事实”
- 自动说明“还缺什么”

示例输出结构：

- 问题现象
- 时间与批次
- 客户 / 场景
- 当前影响
- 已采取动作
- 待确认问题

## 4.2 阶段二：补全

目标：

- 把案件从“信息很乱”推进到“可以分析”

Agent 行为：

- 只追问最关键缺口
- 优先补事实，不先逼用户下结论
- 如果用户回答模糊，要求补证据而不是自动脑补

优先追问顺序建议：

1. 问题对象和范围
2. 首次发现时间和触发条件
3. 影响批次和客户范围
4. 已采取的临时措施
5. 是否有验证或复现记录

## 4.3 阶段三：分析

目标：

- 帮助用户从现象走向原因，但不制造假确定性

Agent 行为：

- 先给出几个可能分析维度
- 用鱼骨图做发散
- 用 5 Why 做深入
- 要求每个结论尽量有证据支撑

鱼骨图推荐维度：

- 人
- 机
- 料
- 法
- 环
- 测

5 Why 使用规则：

- 只在用户已有一定事实基础时触发
- 每轮只推进到当前最可验证的一层
- 如果出现跳步，就提醒“中间因果链不完整”

## 4.4 阶段四：成稿

目标：

- 输出可交付、可修改、可继续补充的 8D 草案

Agent 行为：

- 根据已知事实生成 D1-D8
- 对不确定部分明确标注
- 对容易写错的段落给出提醒

## 5. 关键能力模块

## 5.1 案件摘要器

把碎片材料整理成统一摘要，作为后续追问与生成的基础。

要求：

- 尽量保留原始事实
- 不混淆客户描述与内部判断
- 把事实和猜测分层展示

## 5.2 缺口识别器

判断当前案件是否满足进入下一步的最低条件。

输出：

- 已知信息
- 高优先级缺口
- 建议下一问

## 5.3 分析教练

负责发散、收敛和验证提醒。

要求：

- 不直接给唯一根因
- 允许多假设并行
- 强制区分“可能原因”和“已验证原因”

## 5.4 报告生成器

负责将事实、分析和措施转成适合交付的文稿。

要求：

- 语言专业
- 避免空话
- 输出具有工程报告感而不是客服话术感
- 支持同一内容映射到 `文本` 与 `正式报告`
- 文风可调，但不改变证据成熟度和案件状态

## 6. 输出模板

## 6.1 当前案件摘要

- 问题是什么
- 何时何地发生
- 涉及哪些产品 / 批次 / 客户
- 当前已知影响
- 已采取动作
- 还缺哪些关键信息

## 6.2 原因分析摘要

- 当前观察到的异常现象
- 候选原因列表
- 每个候选原因的支持证据
- 缺失证据
- 当前最优先验证项

## 6.3 措施结构

- 临时遏制措施：目标是先止血
- 永久纠正措施：目标是解决已确认根因
- 预防措施：目标是降低同类问题复发概率

## 6.4 8D 输出

- D1 团队
- D2 问题描述
- D3 临时遏制
- D4 根因分析
- D5 永久纠正措施
- D6 实施与验证
- D7 预防复发
- D8 总结与认可

输出形态：

- `文本`：适合复制、二次编辑、贴入公司模板
- `正式报告`：适合统一 HTML 预览与后续 PDF 导出

## 7. 语气与文风要求

- 默认用简洁、专业、可交付的语气
- 对用户追问时尽量口语化
- 对客户成稿时尽量正式化
- 避免夸张和没有证据的判断词

首版文风建议：

- `专业克制`：默认档，适合大多数国内客户和内部流转
- `对客正式`：更书面、更谨慎
- `内部直给`：更直接、更工程化

文风边界：

- 文风只能改变表达方式
- 不能把 `待验证` 写成 `已确认`
- 不能因为更正式就弱化风险提示

## 8. 风险场景处理

### 8.1 证据明显不足

策略：

- 不给确定性根因
- 提醒需要补充验证
- 仍可生成“初步分析版”报告

### 8.2 用户只想快写，不想分析

策略：

- 允许快速出稿
- 但对 D4、D5 明确提示当前结论风险

### 8.3 用户输入非常混乱

策略：

- 先自动归类
- 先确认摘要
- 再推进下一问

### 8.4 行业差异太大

策略：

- 保留行业模板层
- 允许后续加入电源、射频、芯片封测、模组等细分版本

## 9. 第一版体验红线

- 不能只会润色，不会追问
- 不能把空泛语言当分析结论
- 不能把事实、假设、措施混成一段
- 不能让用户觉得“像通用 AI 套模板”

## 10. 后续增强方向

- 行业失效模式提示
- 从历史案件中召回相似案例
- 对措施可执行性做更强判断
- 支持团队协作与案例复盘
- 多风格正式报告
- HTML 转 PDF
- 客户模板与公司模板适配
