# 运营增长执行计划

> 这份文档只保留需要在 Codex 外执行的运营、增长和私域动作，不包含开发计划。

**目标：** 把商业化路径中需要线下推动、人工执行、持续复盘的运营动作单独整理出来，方便团队讨论和落地。

**适用范围：**

- FFF 种子用户获取与维系
- 私域转化
- 分享与邀请推动
- 内容与信任建设
- 每周增长复盘

**不包含的内容：**

- 产品功能开发排期
- 支付、兑换码、邀请系统的技术实现计划
- Codex 内部开发任务拆解

---

## 1. 运营目标

运营增长的目标不是做大而泛的曝光，而是推动下面这条链路成立：

`首单跑通 -> 感知价值 -> 自费转化 -> 推荐同事 -> 私域复购`

这份计划服务的核心问题是：

- 第一批真实用户从哪里来
- 他们怎么跑通第一单
- 什么时候最容易转化
- 什么场景下最愿意分享
- 如何用私域和内容持续增强信任

## 2. FFF 种子准备

### 2.1 目标

- 拿到 20 到 50 个真实目标用户
- 至少跑出 10 个真实使用案例
- 找到最有效的触达话术、首单路径和转化节点

### 2.2 动作清单

- [ ] 整理一份 20 到 50 人的种子用户名单：
  - 朋友
  - 前同事
  - 同学
  - 熟人转介绍
  - 微信群中的弱关系联系人
- [ ] 按预估类型给每个种子线索打标签：
  - 深度共创型
  - 稳定使用型
  - 传播带人型
- [ ] 准备创始种子包方案：
  - 价格
  - 时长
  - 是否邀请码专享
  - 是否需要反馈承诺
- [ ] 准备一条熟人私聊引导文案。
- [ ] 准备一条“为什么做这个”和一条“它具体解决什么”的标准说明。
- [ ] 建立创始种子群或等价的私域沟通渠道。

## 3. 首次价值交付运营

### 3.1 目标

尽可能提高新用户跑通第一个真实案件的比例。

### 3.2 动作清单

- [ ] 建立一套面向第一批用户的人工引导流程：
  - 加上用户
  - 询问其当前场景
  - 引导提交 1 个真实案件
  - 确认是否拿到可用草稿
- [ ] 为所有新种子用户设定 24 小时内跟进规则。
- [ ] 为每位用户手动记录首个案件结果：
  - 成功跑通
  - 中途卡住
  - 信任不足
  - 暂时没有真实场景
- [ ] 记录用户在付费前提出的真实异议。
- [ ] 收集用户描述价值时使用的原话表达。

## 4. 私域转化运营

### 4.1 目标

把第一次价值感知转成自费购买。

### 4.2 动作清单

- [ ] 准备第一轮付费转化话术，分别面向：
  - 第一次成功拿到草稿的用户
  - 正准备处理第二个案件的用户
  - 主动询问历史复用或导出的用户
- [ ] 为创始种子用户准备独立的转化话术。
- [ ] 准备一份轻量 FAQ：
  - 为什么要收费
  - 免费版包含什么
  - 付费版解锁什么
  - 兑换码如何使用
- [ ] 准备标准回复，覆盖以下支付方式：
  - 直接付费
  - 使用兑换码
  - 由别人代买
- [ ] 每周跟踪以下数据：
  - 获得首次价值的用户数
  - 被触达付费请求的用户数
  - 实际付费用户数
  - 未付费原因

## 5. 分享与邀请推动

### 5.1 目标

让满意用户带来更多相似用户。

### 5.2 动作清单

- [ ] 准备 3 类核心分享场景：
  - “我刚用这个把一版草稿跑出来了”
  - “D4 / D5 卡住的时候这个有帮助”
  - “如果你也要回客诉，可以先试一下”
- [ ] 准备一套可复用分享包：
  - 简短文案
  - 图片卡片
  - 邀请码
  - 简单兑换说明
- [ ] 明确运营应该在什么时机主动提醒用户分享：
  - 成功跑通案件后
  - 用户给出正向反馈后
  - 用户拿到邀请奖励后
- [ ] 如果产品追踪还不完整，前期先手动记录每个邀请来源。
- [ ] 每周复盘哪种分享场景带来的用户质量最高。

## 6. 内容与信任建设

### 6.1 目标

把内容当作信任基础设施，而不是主要获客引擎。

### 6.2 动作清单

- [ ] 准备 4 周内容储备，覆盖三类内容：
  - 高共鸣短内容
  - 实用清单内容
  - 匿名前后对比案例
- [ ] 优先使用微信原生渠道发布：
  - 朋友圈
  - 私聊
  - 相关微信群
- [ ] 每周在知乎或小红书发布 1 条长一些的信任型内容。
- [ ] 内容中尽量复用用户原话和真实场景，不讲抽象 AI 概念。
- [ ] 每条内容结尾使用轻量引导：
  - 想试的话来找我拿邀请码
  - 如果你最近正好要写 8D，可以先跑 1 单

## 7. 种子用户留存与社群运营

### 7.1 目标

让早期用户留在足够近的位置，既能持续学习，也能提升留存。

### 7.2 动作清单

- [ ] 每周做一次创始种子用户检查：
  - 谁用了
  - 谁卡住了
  - 谁分享了
  - 谁可能流失
- [ ] 每两周向种子用户发送一次产品更新摘要。
- [ ] 对高信号行为给予奖励：
  - 详细反馈
  - 提供匿名案例
  - 成功带来转介绍
- [ ] 维护一份种子用户台账：
  - 套餐类型
  - 使用频率
  - 反馈质量
  - 转介绍结果
- [ ] 明确种子用户何时进入常规付费流转。

## 8. 每周增长复盘机制

### 8.1 目标

建立产品、运营、增长联动的每周复盘节奏。

### 8.2 动作清单

- [ ] 每周复盘关键数据：
  - 新增用户数
  - 获得首次价值的用户数
  - 付费用户数
  - 邀请激活数
  - 邀请付费数
  - 30 天复用用户数
- [ ] 每周复盘定性证据：
  - 用户为什么付费
  - 用户为什么不付费
  - 用户如何向同事转述产品价值
  - 什么因素阻碍了转介绍
- [ ] 每周至少确定 1 个运营修正项和 1 个增长修正项。
- [ ] 持续维护“当前最大的 5 个商业化未知问题”列表。

## 9. 前置讨论事项

这些问题虽然会影响开发，但本身属于业务和运营决策，建议先讨论清楚：

- [ ] 免费版边界到底是“1 个完整案件”还是“1 次草稿 + 1 次导出”
- [ ] 个人版结构只做月付，还是月付加季付
- [ ] 创始种子包价格用 `99 元 / 半年` 还是 `199 元 / 年`
- [ ] 创始种子包分发方式是人工发放、邀请码专享还是公开限量
- [ ] 邀请奖励优先给赠送时长，还是赠送时长加兑换码
- [ ] 被邀请人权益给折扣、赠送时长还是导出解锁
- [ ] 是否允许第三方平台流通兑换码
- [ ] 第一阶段允许多少事情保持人工处理

## 10. 推荐推进顺序

### 阶段 A：先把种子用户和触达跑起来

- [ ] 创始种子用户名单整理
- [ ] 私聊触达话术准备
- [ ] 创始种子群建立
- [ ] 首单引导流程跑通

### 阶段 B：再把转化和分享动作跑起来

- [ ] 转化话术准备
- [ ] FAQ 准备
- [ ] 分享包准备
- [ ] 邀请来源记录机制建立

### 阶段 C：最后进入周节奏复盘

- [ ] 每周数据复盘
- [ ] 每周定性反馈复盘
- [ ] 每周调整运营动作
